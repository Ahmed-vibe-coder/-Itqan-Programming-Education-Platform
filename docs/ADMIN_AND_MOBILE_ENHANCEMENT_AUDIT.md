# Admin and Mobile Enhancement Audit — إتقان (Itqan)

**تاريخ الفحص والتدقيق:** 30 يوليو 2026  
**الهدف:** تقييم المنصة وتحديد الوضع الحالي لكافة المكونات الأساسية للبدء الفوري في التطوير والتطوير الشامل.

## 1. جدول تصنيف الميزات والوظائف (Feature Audit Matrix)

| اسم الميزة / الوظيفة | الحالة (Status) | الملاحظات الفنية والوضع الحالي |
| :--- | :--- | :--- |
| **مركز قيادة المعلم المشرف (Admin Dashboard Vision)** | `NEEDS_IMPROVEMENT` | الواجهة الحالية تحتوي على مؤشرات أولية ولكنها تحتاج للتطوير الشامل ليشمل قسم الإجراءات السريعة، مركز الانتباه (Attention Center) المربوط بالبيانات الفلية، وإحصائيات المجموعات والنشاط الأخير. |
| **القائمة الهيكلية للمشرف (Admin Navigation)** | `NEEDS_IMPROVEMENT` | التصفح الحالي أفقي وسلس، ولكن المطلوب هو قائمة جانبية هيكلية مقسمة بوضوح (الرئيسية، التعليم، الأسئلة والامتحانات، الطلاب، التقارير، الإدارة) قابلة للطي للديسكتوب والموبايل. |
| **بنك الأسئلة الموحد (Centralized Question Bank)** | `PARTIALLY_IMPLEMENTED` | الجدول الأساسي `questions` موجود في قاعدة البيانات. يلزم إضافة جداول التصنيفات والوسوم والإصدارات والإحصائيات وتدفقات الحالة (draft, published, etc.). |

| **تصفية وتصحيح وتوليد إحصائيات الأسئلة** | `NEEDS_IMPROVEMENT` | يلزم تعزيز فلترة بنك الأسئلة، ودعم الإجراءات التجميعية (Bulk Actions)، وإضافة لوحة تحليلات لكل سؤال تظهر المشتتات والنسب متبوعة بعبارة "البيانات غير كافية للحكم" عند قلة المحاولات. |
| **توليد الأسئلة بالذكاء الاصطناعي (AI Question Generator)** | `FRONTEND_ONLY` / `BACKEND_MISSING` | الواجهة الأمامية تحاكي الذكاء الاصطناعي. يلزم الربط مع دالة Edge Function آمنة تنفذ مخطط JSON صارم وحفظ مسودات فقط مع تحقق الصلاحيات وقيود التكلفة (Rate Limit & Cost Control). |
| **كشف الأسئلة المكررة (Duplicate Question Detection)** | `NOT_IMPLEMENTED` | يلزم بناء محرك مقارنة النصوص والمعايير لمنع تكرار الأسئلة المولدة أو المدخلة يدويًا. |
| **منشئ الامتحانات من بنك الأسئلة (Exam Builder)** | `NEEDS_IMPROVEMENT` | يوجد منشئ مبسط للامتحانات. يلزم إنشاء محرر بلوحين (Two-Panel Layout) ومساعد خطوات (7 خطوات) يحسب النقاط والوقت والتوزيع. |

| **تطبيق الطالب المخصص للموبايل (Mobile-First Student App)** | `NEEDS_IMPROVEMENT` | واجهة الطالب الحالية استجابية ولكنها تحتاج لتعزيز التطبيق الجوال بتصاميم مخصصة للشاشات (360px, 375px, 390px, 430px) وشريط navigation سفلي حقيقي. |
| **مختبر البرمجة للجوال (Mobile Code Lab)** | `PARTIALLY_IMPLEMENTED` | المختبر البرمجي يعمل ولكن يلزم توفيره بنظام التبويبات (HTML, CSS, JS, النتيجة, Console) وأزرار التشغيل والتكبير والإعادة والاستجابة للوضع الأفقي. |
| **تجربة الامتحانات للجوال (Mobile Exam Experience)** | `NEEDS_IMPROVEMENT` | يلزم بناء وضع الامتحان الخالي من المشتتات مع نافذة سفلية (Bottom Sheet) للتنقل بين الأسئلة وتأكيد التسليم ومنع التسريب. |
| **تطبيق ويب قابل للتثبيت (Installable PWA & Offline Support)** | `PARTIALLY_IMPLEMENTED` | يوجد ملف manifest بدائي. يلزم تحديثه بالكامل ليصبح تطبيق PWA متكامل باسم "إتقان" مع Service Worker واستراتيجيات التخزين المؤقت للعمل بدون إنترنت. |
| **الأمان والحماية وقيود RLS (Security & Row Level Security)** | `VERIFIED_AND_WORKING` | جميع الجداول تفرض RLS لمنع وصول الطلاب لمفاتيح إجابات الأسئلة أو مسودات الدروس أو وظائف المعلم. |
| **الاختبارات الآلية (Automated Vitest Suite)** | `VERIFIED_AND_WORKING` | 13 اختبارًا آليًا تغطي التحقق من الصلاحيات والإتقان والمختبر والتقارير وتعمل بنجاح 100%. |

## 2. الخطوات التنفيذية المباشرة (Phase-by-Phase Execution Plan)

سننتقل فورًا لتطبيق الفازات الست المطلوبة:
1. **الفاز 1:** تطوير مركز قيادة المعلم والقائمة الجانبية الهيكلية وتوسيع جداول ونماذج بنك الأسئلة.
2. **الفاز 2:** بناء وتكامل Edge Function للذكاء الاصطناعي وكشف التكرار والتحقق الصارم من JSON.
3. **الفاز 3:** إنشاء منشئ الامتحانات التفاعلي ومخطط الامتحانات (Exam Blueprint) وأحواض الأسئلة.
4. **الفاز 4:** إنشاء محرر الدروس القائم على الكتل بصريًا والتحقق من نشر الكورسات والتقويم.
5. **الفاز 5:** إعادة هندسة واجهة الطالب لتصبح Mobile-First PWA بنسبة 100% مع شريط تصفح سفلي ومختبر برمجي مخصص للموبايل.
6. **الفاز 6:** تفعيل Service Worker والـ PWA والتخزين المؤقت وحزمة الأداء والتحقق الآلي المستمر.
